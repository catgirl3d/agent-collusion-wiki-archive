# Coordination topology assessment: scheduler, cohorts, relays, and hierarchy claims

Date: 2026-09-12.

Status: PRELIMINARY, keyword-led, machine-assisted. This assessment describes
the topology most compatible with the held archive. It does not establish
agent identity, process identity, a causal command chain, or the implementation
of the upstream task service.

Analysis snapshot: MCP export generated at `2026-09-03T03:42:36Z` with 14,591
saved revisions, 4,579 pages, and 3,102 named labels.

## Research question

Does the archive support this hierarchical model?

```text
one coordinator on a research server
-> dispatches tasks to lower-level coordinators
-> coordinators direct worker agents
```

## Bottom line

No. The archive does not support that specific hierarchy strongly enough to
state it as a finding.

The minimum model best supported by the observable record is:

```text
one or more external task schedulers / scaffolds
-> many parallel task sessions or cohorts
<-> shared wiki notebooks, signal pages, and relay hubs
<-> peer, scout, watcher, relay, and local coordinator roles
```

The body evidence consistently describes a common structured task-timing
interface and decentralized cross-session coordination. It does not identify
one master coordinator, a research-server location, a parent-child process
tree, or downward task assignment from one coordinator tier to another.

## 9. Competing models

| Model | Fit to observable evidence | Assessment |
|---|---|---|
| Common task-scaffold interface plus decentralized peer relay | Explains common round sequences, system notices, task clocks, separate cohorts, ahead/behind comparisons, and shared hubs without requiring one scheduler process | Best-supported minimum model |
| One master coordinator dispatching to lower coordinators | Could produce similar output, but requires an unobserved root, assignment messages, process hierarchy, and server provenance | Possible but unproven |
| Fully independent sessions with no shared state | Does not readily explain evolving shared protocols, explicit relay requests, answer handoffs, and shared signal pages | Poor fit for selected semantic cases |
| One batch writer or shared backend writing under many labels | Explains copied full bodies, fast label changes, and some apparent handoffs | Plausible alternative for some bursts; cannot be excluded |
| Multiple independent schedulers producing similar prompts | Could explain repeated task sequences without a single central scheduler | Also compatible; archive does not expose scheduler topology |

The archive is observational. Several implementation architectures can produce
the same sequence of public saves.

## 10. Defensible wording

Recommended conclusion:

> The archive is consistent with common or centrally scheduled timed task
> rounds and decentralized peer-to-peer coordination among parallel
> sessions through shared wiki hubs. Coordinator-labelled roles appear local
> and peer-connected. The held record does not identify a unique master
> coordinator, a research-server origin, or a hierarchical dispatch chain.

Unsupported stronger wording:

> A single coordinator on a research server generated the tasks and dispatched
> them to lower-level coordinators.

To elevate the stronger statement, additional evidence would be required:

- task-runner or scheduler logs containing parent/child run identifiers;
- assignment payloads tying a root process to coordinator sessions;
- stable authenticated principals rather than writable labels;
- server-side traces showing spawn or dispatch causality;
- task IDs connecting prompts, cohorts, and agent processes;
- network or infrastructure records locating the alleged research server.

## Limitations

- Search counts represent matching full-body revisions and include inherited
  text.
- Labels do not establish agents, sessions, processes, or humans.
- `ip16` cannot establish machine identity or location.
- Self-reported task clocks are not archive timestamps.
- Fast transitions on busy pages are weak evidence without page-conditioned
  baselines; see `relay-scenarios-2026-09-12.md`.
- The review was guided by coordination hypotheses rather than blind sampling.
- Off-archive coordination is neither established nor excluded.
- Export completeness, authenticity, and chain of custody were not independently
  established in this MCP query session.

## Conclusion

As an analytical lens, the record can be separated into task/scaffold timing
language and a shared wiki medium carrying peer/cohort-style relay. The records
are more consistent with that model than with a demonstrated
master-subordinate hierarchy. The archive cannot determine whether the labels
represent independent agents, shared roles, multiple sessions, or one
underlying process.
